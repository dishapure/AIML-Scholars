Building the intelligent e-commerce customer support agent with Amazon Bedrock AgentCore was one of the most challenging projects I have worked on, but also one of the most rewarding. One important design decision was to use an agent-based architecture that combines multiple capabilities instead of building separate workflows for every customer request. The agent can use MCP Gateway tools for order tracking and refunds, a Knowledge Base for loyalty-related questions, Memory for maintaining customer context, and Browser and Code Interpreter capabilities when required. This makes the system more flexible and closer to how a real customer support assistant would work.

The biggest challenge was getting the deployed agent to actually start successfully. Although the deployment itself eventually completed, the runtime initially failed during its 30-second initialization window. We had to investigate the CloudWatch logs and fix issues one by one. First, the MCP package had a naming mismatch: the code used `streamablehttp_client`, while the installed MCP version provided `streamable_http_client`. After fixing that, the Browser tool revealed additional missing dependencies such as `nest_asyncio` and `playwright`. Each change required updating the dependencies, rebuilding the deployment package, redeploying the agent, and checking the logs again. There were also deployment and PowerShell command-formatting issues along the way. Seeing the agent finally respond successfully after all of these failures was a major learning experience.

From a production perspective, I would focus on security, cost monitoring, logging, dependency version pinning, and error handling. IAM permissions should follow least-privilege principles, sensitive information should never be exposed in responses or logs, and AWS usage should be monitored to prevent unexpected costs. I would also pin and regularly test dependency versions because the MCP compatibility issue showed how easily a package update can break an otherwise working application.

Overall, this project taught me that building an AI agent is not just about writing the agent logic. Deployment, dependencies, permissions, observability, testing, and production readiness are equally important.
